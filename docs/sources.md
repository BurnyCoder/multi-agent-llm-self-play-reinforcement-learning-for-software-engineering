# Sources, reuse, and interpretation

This project is a local multi-agent adaptation of existing bug/repair self-play research. No priority or novelty claim is established for this combination. The [independent claim ledger](https://github.com/BurnyCoder/multi-agent-llm-self-play-reinforcement-learning-for-software-engineering/blob/main/reports/independent-audit-2026-11-12.md) distinguishes implementation, execution, and interpretation.

| Component | Source | Use and boundary |
| --- | --- | --- |
| Repository bug injection and repair | [Self-play SWE-RL, v3](https://arxiv.org/html/2512.18552v3) | Bug patch, test weakening, oracle restoration, consistency checks, solve-rate-based injection and binary repair rewards ([§2.3–2.4, Eqs. 1–2](https://arxiv.org/html/2512.18552v3#S2.SS3)), and higher-order bugs. SSR's curriculum emerges from self-play; it is not a separate reward. The Python/pytest runner is an adaptation, not SSR's general artifact discovery. |
| Policy objective | [CWM, Appendix C](https://arxiv.org/html/2510.02387v1#A3) | Generated-token masks, length-weighted centered returns, asymmetric clipped likelihood ratios, and fixed token-capacity scaling. The clip thresholds used here (ε_low = 0.2, ε_high = 0.25, i.e. [0.8, 1.25]) and the no-KL and no-σ-normalization choices are stated in [CWM Section 5.2](https://arxiv.org/html/2510.02387v1#S5.SS2), not in Appendix C. Team-level credit accounting is this project's extension. |
| Concurrent subagents | [OpenCode pinned source](https://github.com/anomalyco/opencode/blob/e761e265d2d5e6ff4a1c0756ab8d8eeee0db501e/packages/core/src/tool/plugin/subagent.ts) | Fresh/resumable child sessions, explicit delegation, and background work. Reimplemented in Python for trace accounting; model overrides are intentionally unavailable. [MIT license](https://github.com/anomalyco/opencode/blob/e761e265d2d5e6ff4a1c0756ab8d8eeee0db501e/LICENSE). |
| Base model | [Qwen3.5-2B](https://huggingface.co/Qwen/Qwen3.5-2B) | Original model revision is pinned in the run manifest. Apache-2.0 weights; no claim that pretrained knowledge is uncontaminated. |
| Local adapter training | [Unsloth Qwen3.5 guide](https://unsloth.ai/docs/models/qwen3.5/fine-tune.md), [implementation](https://github.com/unslothai/unsloth/blob/main/unsloth/models/vision.py) | BF16 shared language-model LoRA; measure actual memory rather than treating documentation estimates as guarantees. Library is [Apache-2.0](https://github.com/unslothai/unsloth/blob/main/LICENSE); the locked `unsloth-zoo` dependency is [LGPL-3.0-or-later](https://pypi.org/project/unsloth-zoo/2026.10.10/), and the [Unsloth notebooks](https://github.com/unslothai/notebooks/blob/main/LICENSE) are LGPL-3.0. Do not copy LGPL notebook code into this repository. |
| Human-bug evaluation | [SWE-bench harness](https://www.swebench.com/SWE-bench/guides/evaluation/), [Verified dataset](https://huggingface.co/datasets/SWE-bench/SWE-bench_Verified) | Fixed held-out task selection, official scoring, and no reference fixes in agent context. Underlying repository licenses remain applicable. |
| Transfer failure motivation | [Anchored Self-Play for Code Repair](https://arxiv.org/html/2607.03523v1) | Function-level BugSourceBench experiments motivate checking bug-source shift; they do not establish failure or success of this repository-level adaptation. Its reference mixing, embedding rewards, and standard-deviation-normalized advantages are not used here. |
| Paired uncertainty | [SciPy bootstrap documentation](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.bootstrap.html) | Task-paired percentile resampling implemented with the Python standard library. These intervals condition on one checkpoint; they do not measure training-seed variance. Degenerate intervals are flagged. |
| Likelihood preflight | [PyTorch mixed precision](https://docs.pytorch.org/docs/2.14/amp.html), [Qwen cached/full-forward numerical analysis](https://github.com/huggingface/transformers/issues/46190), [CWM Appendix C](https://arxiv.org/html/2510.02387v1#A3) | Match BF16 autocast between generation and scoring. Preserve the actual sampled log probabilities; never replace them with trainer recomputations. A forced-token cached replay checks probability recording separately from full-forward BF16 numerical drift. The amended engineering gate requires replay agreement and no pre-update clipping on the diagnostic sample; the papers do not prescribe that gate or promise numerical equality. The upstream issue is evidence for a possible mechanism, not proof of this run's cause. |
| Paper rendering | [ReportLab User Guide](https://www.reportlab.com/docs/reportlab-userguide.pdf) | Platypus paragraphs, tables, images, and page callbacks. Report text and numerical claims are generated from saved run records. |
| Procedural-bug controls | [SWE-smith](https://github.com/SWE-bench/SWE-smith) | Reference for executable validation of synthetic bugs and controls. Any implemented restricted mutations are documented separately from the learned injector. |

## Claim boundaries

An executable test is an oracle for the specified behavior, not a proof of complete program correctness. A training update is evidence of weight optimization, not of generalization. A comparison with the unchanged policy tests the combined pipeline; attributing an effect to subagents requires the planned ablations. Unrun controls and missing measurements are explicitly unscored. Both positive and negative observations belong in the generated reports.

## Human evaluation implementation boundary

[The local evaluator](https://github.com/BurnyCoder/multi-agent-llm-self-play-reinforcement-learning-for-software-engineering/blob/main/src/multi_agent_ssr/evaluation.py) calls the installed, locked official SWE-bench `make_test_spec` and `run_instance` APIs. It preserves their test oracle and parser. Its Docker client wrapper disables networking, drops capabilities, and applies memory, process, and CPU limits; these isolation settings differ from upstream defaults. The grader receives reference test patches only on the host, after the agent finishes.

The agent image is derived from the official dependency image with its original `/testbed` checkout and Git history removed. A separate source copy is checked against the pinned base commit, allowing mode-only changes made by the image builder, and receives no original Git metadata. Agent imports resolve to `/repo` or `/repo/src`. Committed official image digests remain fixed across preparation and fresh clones; rebuilt dependency-image IDs are recorded locally.

The upstream grader caches reports by run ID without comparing a new submitted patch. Each actual grading attempt therefore receives its own ID, while the evaluator reuses a task only after a completed outcome has been recorded. Infrastructure errors remain unscored. Invalid agent artifacts count as failures, and context-budget exhaustion is evaluated using the available patch when the official oracle can run. The generated reports retain coverage and distinguish the preregistered interval decision from the limitations of a degenerate bootstrap interval.

## Installed-source checks and reporting semantics

[Source verification](https://github.com/BurnyCoder/multi-agent-llm-self-play-reinforcement-learning-for-software-engineering/blob/main/reports/source-verification-2026-11-12.json) records installed-versus-locked versions and byte comparisons against upstream. The checked [SWE-bench grader](https://github.com/SWE-bench/SWE-bench/blob/ca6e4e0d252f32f8762625b73575d5dee49d0a5a/swebench/harness/grading.py), [Qwen forward implementation](https://github.com/huggingface/transformers/blob/v5.17.0/src/transformers/models/qwen3_5/modeling_qwen3_5.py), and [PEFT base-revision loader](https://github.com/huggingface/peft/blob/v0.21.2/src/peft/auto.py) match the installed files. Moving documentation links provide context; pinned sources and the lockfile identify the audited implementation. This audit did not upgrade dependencies or rerun a model.

The report schema retains raw condition `trained` for compatibility and displays it as **final condition**. `artifact_validation_checks` counts saved accepted and rejected checks; `valid_artifacts` counts accepted checks; `validated_artifacts` is the legacy alias for checks, not accepted bugs. `pass_to_pass_test_failures` counts official failure-list entries, including missing parsed tests where the grader classifies them as failures; `pass_to_pass_regressions` is a legacy alias and does not establish causality. Missing optimizer measurements are `null`, not zero. Checkpoint equality requires matching saved adapter/configuration hashes and pinned base identities. See [evidence.py](https://github.com/BurnyCoder/multi-agent-llm-self-play-reinforcement-learning-for-software-engineering/blob/main/src/multi_agent_ssr/evidence.py), [reporting.py](https://github.com/BurnyCoder/multi-agent-llm-self-play-reinforcement-learning-for-software-engineering/blob/main/src/multi_agent_ssr/reporting.py), and their regression tests.

The browser shows complete saved event text but replaces large token arrays with their counts. Original arrays remain in the exported raw records. Model-generated explanations, tool-like text, and completion claims are historical outputs, not independently verified facts; only actual harness events establish which tools ran. The static dashboard updates when the report command is rerun; it is not a live training telemetry service.
